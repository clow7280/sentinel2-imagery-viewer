# Sentinel-2 影像浏览

浏览 Sentinel-2 L2A 10 米真彩色影像的 Web 应用，无需注册与密钥，线上地址为 <https://sentinel2.c410.space>。
影像检索走 Earth Search 的 STAC 接口，像元从 AWS 公开桶中的 COG 按窗口读取，由后端重投影并镶嵌成 WebP 地图瓦片。
所有上游数据都经部署在东京的后端转发并落盘缓存，国内不开代理也能使用。

## 功能

- 影像按 Sentinel-2 的 MGRS 100 km 分幅划分区域，各区域自动显示各自近 3 个月内的最佳影像
  - 7 级及以上且视野不超过 36 平方度时，地图停止移动后自动检索视野内的影像：先取云量不超过 20% 的景，一景都没有的区域再按云量从低到高补检
  - 每个区域先看覆盖，只在缺测比该区域最少缺测多不超过 5 个百分点的景中挑，再取云量最低的，云量相差不超过 2 个百分点时取更新的
  - 首选景或手动选的日期有缺测时，从其他每条相对轨道各取云量最低的一景在下层补齐；相对轨道号取自产品名中的 `_R020_` 一类字段
  - 后端合成时每景只填自己的方格，影像接缝与区域边界一致
  - 服务器已缓存的影像在 4 级以上始终显示，缩小到检索范围之外也不消失
- 点击影像在底部弹出该区域的时间轴，选中的区域边界加粗；关闭时间轴或再次点击同一区域即收起并取消选择
  - 默认近 3 个月、云量不超过 20%，拖动平移、滚轮缩放时间段，也可手动输入起止日期，尚未检索的时间段以斜纹表示
  - 每个有影像的日期一根柱，高度为对分幅的数据覆盖率，颜色深浅表示云量，星标为自动挑选的日期，蓝框为正在显示的日期
  - 悬停查看成像时刻、卫星、覆盖率与云量；点击日期在该区域预览，点「保存区域选择」后保留，未保存时关闭时间轴即恢复原来的影像
  - 保存的选择连同所用的景存在浏览器本地，再次打开时不等检索就能显示，「恢复自动」可清除
  - 平均每月不足 1 个可用日期时提醒提高云量上限
- 地图默认为地球投影，缩小时为星空背景下的三维地球，放大后自动过渡为墨卡托平面
- 底图的国界与注记按中国视角绘制，取自本机 osm-cn-basemap 项目
- 右上角图层面板按分组列出以下图层，每行有图例图标与开关，采集计划与扫描带在放大后置灰；详细信息点击要素后在弹窗中查看
- 右下角图例贴底、每行一条、只列出当前可见的图层；时间轴始终水平居中，会压到图例时左右对称收窄，过窄时上移到图例上方
  - 卫星影像与影像边界：影像边界即区域划分，画出有影像的各 MGRS 分幅方格
  - 地名注记、海图标志
  - 主要航路：橙色为大洋航路，按航运繁忙程度分主要、次要、支线三级；紫色为北极航道，含东北航道与北方海航道、西北航道各水道与跨极航线，分析见 [北极航道 2025 年与 2026 年通航情况](docs/北极航道-2025-2026.md)
  - 卫星采集计划：4 级及以下显示 ESA 计划采集条带，日期在该项下方选择；ESA 每两周发布一次，每份覆盖约 18 天
  - 卫星扫描带：4 级及以下显示 S2A、S2B、S2C 的实时位置、前后各半圈约 50 分钟的地面轨迹与 290 km 扫描带，按 TLE 每 10 秒推算一次
- 标题右侧的信息窗口与标题等高，常驻显示，宽度随内容变化、不超过图层面板
  - 卫星图标亮起表示当前缩放与视野在影像检索范围内，即 7 级及以上且视野不超过 36 平方度，加载或检索时图标外圈转动
  - 文字内容 5 秒不变后收起，只留图标，悬停时展开
  - 显示加载与检索进度，以及最近一批影像瓦片的请求、完成、服务器已缓存、平均耗时与下载量
  - 检索、瓦片、采集计划、轨道根数等请求失败时以红字显示最近的错误 30 秒，悬停可查看最近 20 条
- 左下角比例尺旁显示鼠标经纬度、缩放级别与底图署名，完整的版权声明、版本号与构建时间在标题右侧的关于窗口中

## 目录结构

| 目录      | 内容                                                          |
| --------- | ------------------------------------------------------------- |
| `web/`    | 前端，Vite、MapLibre GL 6 与 Tailwind 4                       |

## 本地开发

```bash
pnpm install
```

```bash
pnpm dev
```

`pnpm dev` 同时启动前端 <http://localhost:5173> 与后端 `127.0.0.1:8787`，前端把 `/api` 转发给后端。
后端开发时设置了 `NODE_USE_ENV_PROXY=1`，本机配置了 `HTTPS_PROXY` 等环境变量时经该代理访问上游，缓存写在 `server/.cache/`。

## 部署

站点部署在腾讯云东京轻量服务器 `self-tcc-las01-tyo`，Caddy 提供 HTTPS、静态前端并把 `/api` 反代到后端，后端由 systemd 单元 `sentinel2-api` 运行。

```bash
ssh self-tcc-las01-tyo 'bash -s' < deploy/setup-host.sh
```

```bash
pnpm release
```

前者只在新主机上执行一次，安装 Caddy 与 Node.js 24 并建立目录；后者在本机构建后同步产物与配置，重启服务并做健康检查。

| 位置                               | 内容                                               |
| ---------------------------------- | -------------------------------------------------- |
| `/srv/sentinel2/web/`              | 前端静态文件                                       |
| `/srv/sentinel2/server/index.mjs`  | 后端单文件包                                       |
| `/srv/sentinel2/server/node_modules/` | sharp，含原生模块不进单文件包，发布时按本机锁定版本安装 |
| `/etc/caddy/sites/sentinel2.caddy` | 站点配置，主配置 `/etc/caddy/Caddyfile` 只负责引入 |
| `/var/cache/sentinel2/`            | 上游缓存，由 systemd 的 `CacheDirectory` 管理      |
| `/var/log/caddy/sentinel2.log`     | 访问日志                                           |

查看后端日志用 `journalctl -u sentinel2-api`，清空缓存可停服务后删除 `/var/cache/private/sentinel2` 下的内容。

## 后端缓存

| 接口                    | 上游                                   | 缓存时长                   |
| ----------------------- | -------------------------------------- | -------------------------- |
| `POST /api/stac/search` | Earth Search STAC                      | 按请求体缓存 1 小时        |
| `/api/s2/{z}/{x}/{y}.webp` | 服务端渲染的影像瓦片，读取 AWS `sentinel-cogs` 的 TCI | 渲染结果与 COG 1 MiB 分块均长期缓存 |
| `/api/esa/plans`        | ESA 采集计划列表页                     | 6 小时                     |
| `/api/esa/kml/:name`    | ESA 采集计划 KML                       | 7 天                       |
| `/api/tle`              | CelesTrak                              | 2 小时                     |
| `/api/ofm/…`            | OpenFreeMap 样式、矢量瓦片、字体与图标 | 1 天，带版本号的路径 30 天 |
| `/api/seamark/…`        | OpenSeaMap 海图标志瓦片                | 7 天                       |

`/api/cached-scenes` 返回已缓存影像的景编号，前端按编号经 STAC 取元数据，参与各区域的自动挑选，缩小后这些区域仍显示影像。
景编号取自分块元数据中记录的 COG 路径，后端启动时与缓存淘汰后扫描分块元数据重建，读写分块时补登记。

缓存按类别设磁盘上限，影像分块 20 GB、底图与海图瓦片 4 GB、其余 1 GB，每 15 分钟按最近访问时间淘汰到上限的九成。
上游失败时若有过期副本则返回旧副本，连接错误与 502、503、504 等待 1 秒后重试一次。
缓存文件先写带随机串的临时文件再改名，重叠的 COG 分块区间并发写同一分块时互不干扰，写入失败只记日志、不影响响应。
后端启动时与此后每 6 小时预取覆盖前一日到后两日的采集计划 KML，避免用户打开当日计划时等待 ESA 慢速下载。
站点公开访问，后端只转发上表中固定的上游与路径格式，影像瓦片限 4 到 15 级、每个瓦片最多 24 景且景编号须能在 STAC 中查到，每个 IP 每分钟最多 3000 次请求。

## 数据来源

| 数据     | 来源                                                                                                        | 访问方式   |
| -------- | ----------------------------------------------------------------------------------------------------------- | ---------- |
| 景检索   | [Earth Search STAC](https://earth-search.aws.element84.com/v1)                                              | 经后端缓存 |
| 影像像元 | AWS 公开桶 `sentinel-cogs` 中的 TCI 与 SCL COG                                                              | 经后端缓存 |
| 采集计划 | [ESA Sentinel-2 Acquisition Plans](https://sentinels.copernicus.eu/copernicus/sentinel-2/acquisition-plans) | 经后端缓存 |
| 轨道根数 | [CelesTrak](https://celestrak.org/) 的 TLE                                                                  | 经后端缓存 |
| 底图     | [OpenFreeMap](https://openfreemap.org/) 矢量瓦片，样式取自 osm-cn-basemap                                   | 经后端缓存 |
| 国界     | [Natural Earth](https://www.naturalearthdata.com/) 中国视角边界与 [cnmaps-data](https://github.com/cnmetlab/cnmaps-data) 南海十段线 | 随应用打包 |
| 海图标志 | [OpenSeaMap](https://www.openseamap.org/) seamark 瓦片                                                      | 经后端缓存 |
| 大洋航路 | [Shipping-Lanes](https://github.com/newzealandpaul/Shipping-Lanes)，CC BY 4.0                               | 随应用打包 |
| 北极航道 | [Eurostat MARNET](https://github.com/eurostat/searoute)，EUPL-1.2，部分段人工数字化                         | 随应用打包 |

`web/public/basemap/` 下的样式、边界瓦片与图标由 `node web/scripts/sync-basemap.mjs` 从本机 `~/repo/osm-cn-basemap` 的生成物同步，路径改写为本站地址，字形与矢量瓦片仍走 `/api/ofm` 转发。
该项目重新生成后再执行一次同步，环境变量 `OSM_CN_BASEMAP` 可指定其他位置。

`web/public/shipping-lanes.geojson` 由 Shipping-Lanes v1 原始数据精简而来，只保留航路等级字段，坐标保留 4 位小数。
`web/public/arctic-routes.geojson` 由 MARNET 的 `marnet_plus_100km.gpkg` 按最短路径拼接，再加上按公开资料人工数字化的示意段，后者在地图上以虚线显示。
两者穿过陆地的部分按 Natural Earth 10m 海岸线在水域内重新寻路，只表示大致走向。
原始数据的苏伊士至亚丁湾段偏离航道，运河段东偏约 0.2°，红海段贴沙特海岸后斜穿，已重画：运河用 OpenStreetMap 的运河中心线，北口汇合点移到塞得港进港航道口；运河南口到亚丁湾用 MARNET 20 km 航路网按大圆距离求最短路径。
各航道的通航统计引自 PAME: Arctic Ship Traffic Data、CHNL 与 SPRI 等公开资料，出处列在分析文档末尾。

影像使用须注明 Contains modified Copernicus Sentinel data。

## 实现要点

影像瓦片在后端 `server/src/render.ts` 中渲染。
前端只挑出与瓦片相交的景，按合成优先级把景编号放进 `/api/s2` 的查询参数，高分屏请求 512 像素的 `@2x` 瓦片。
后端按景编号经 STAC 取 COG 路径与 UTM 参数，在 8 乘 8 的控制格网上用 proj4 把经纬度换算到各景的 UTM 坐标，其余像元双线性插值，再按景的优先顺序读取 COG 窗口，逐像元写入尚未填充的位置，最后用 sharp 编码为 WebP。
每景只写入所属 MGRS 100 km 方格内的像元：分幅左上角与方格西北角只差几十米，取整到 100 km 即得方格，分幅向东、向南多出的约 9.8 km 重叠带不参与合成。
层级选择允许 1.5 倍以内的上采样；deflate 用 Node 原生 zlib 异步解压，不阻塞事件循环；同时渲染 12 个瓦片，让回源等待相互重叠。
同一瓦片的并发请求共享一次渲染；地图移走后浏览器取消请求，所有请求方都断开时渲染随之取消：排队中的不再开始，进行中的在发起新的 COG 分块读取前停下，已发出的回源请求照常完成并写入分块缓存。

改为服务端渲染前，浏览器直接下载 COG 的 1024 像素整块，一屏常需 4 到 16 MB，而东京主机出口带宽实测只有约 18 Mbps。
改后一屏 26 个 512 像素瓦片约 1.2 MB，线上实测如下：

| 情形                               | 一屏加载 |
| ---------------------------------- | -------- |
| 瓦片已渲染并缓存                   | 约 0.9 秒 |
| COG 已缓存、瓦片未渲染             | 单瓦片渲染 30 到 80 毫秒 |
| 新区域或新日期，需从美西回源 COG   | 约 7 到 9 秒 |

冷启动的瓶颈是东京到 AWS 美西的回源，单个 1 MiB 分块约 0.5 到 1.1 秒，带宽在 1.3 到 10 MB/s 间波动。

主机出口带宽由所有响应共用，大响应会拖慢同时进行的影像瓦片。
Earth Search 默认返回每景全部资产，一页 50 景近 1 MB，前端检索时用 `fields` 排除资产与要素链接，降到约 30 KB。
Caddy 默认不压缩 GeoJSON、KML 与矢量瓦片，站点配置中补上这些类型后，检索一页约 3 KB，单颗卫星的采集计划 KML 从 2.2 MB 降到约 320 KB。

每次发布后静态文件的 ETag 会变，Chrome 带着缓存中旧的 ETag 对 PMTiles 发 `If-Range` 范围请求时会拿到整个文件的 200 响应，PMTiles 客户端因此报错，所以 `*.pmtiles` 设为 `Cache-Control: no-store`。

## 已知限制

- 自动检索从 7 级开始、视野限制在 36 平方度以内，单次检索最多取 1500 条；4 到 7 级只显示已知的景，单个瓦片最多合成 24 景，大范围缩小时部分区域可能空缺
- 云量 `eo:cloud_cover` 是整景统计值，自动挑选只能保证整景最晴，不保证视野内每处无云
- 采集计划的条带由 KML 中的角点连接而成，与实际产品边界存在偏差
